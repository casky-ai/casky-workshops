The Loopline homepage

Loopline is a fictional customer-support SaaS, "vibe-coded" in a weekend and shipped straight to its first 40 customers, no security review, per the FastLane / SpeedBump story. It ships two real gotchas from the sourced Top 10: Row-Level Security left off, and a Supabase service-role key sitting in the client bundle.

Prerequisites

  • Docker Desktop (or any Docker runtime), running.
  • This repo, checked out; every command below runs from fastlane/.

How Loopline broke it

Lovable scaffolded Loopline's database. It never turned Row-Level Security on for the customers table, not disabled by a developer, never enabled at all. Weeks later, a security blog post scared the founder into fixing one table: tickets got a policy, but it was USING (true), which matches every row for every requester. Looks fixed in a schema diff. Isn't. customers was never revisited.

Separately, an env var named NEXT_PUBLIC_SUPABASE_SERVICE_ROLE_KEY shipped Supabase's admin key straight into the browser bundle, because the coding assistant didn't flag what NEXT_PUBLIC_ does in Next.js. Nobody caught it before it shipped. Full story: NARRATIVE.md.

The five-minute check

Two scripts, no special access, same two checks from the Top 10 blog post, already in fastlane/, pointed at the local container instead of a real app.

Check 1: does the anon key read every row?

cd casky-workshops/fastlane
./check_1_rls.sh

Runs curl -s "http://localhost:8787/rest/v1/customers?select=*" -H "apikey: <anon key>" and explains the result. Returns all five Loopline customer rows, no login required. The apikey is the public "anon" key, meant to ship to every browser. rowsecurity: false is Postgres's own flag: RLS was never turned on for this table, so the public key alone is enough to read everything.

Check 2: is a secret sitting in the shipped bundle?

./check_2_secrets.sh

Runs curl -s http://localhost:8787/_next/static/chunks/app-a91f3c2e.js | grep -oiE '(service_role|sk-live-|AKIA)[A-Za-z0-9_.":-]{5,}' and explains the result. Returns the Supabase service-role key: Supabase's admin key, meant only for trusted server-side code. The anon key (check 1) respects RLS when RLS is configured; the service-role key bypasses RLS entirely, by design, correctly configured or not.

This is synthetic data

The customer rows, the domain, and the keys above are all fabricated for this workshop (see NARRATIVE.md). No real company, customer, or credential is involved.
